Project history

DocGeo extends DGPad: the same way of building, with native 3D and vector drawing.

2012-2017: DGPad

Development of DGPad starts in spring 2012 and stops in 2017. The software stays online and its figures still circulate: DocGeo opens them.

2017-2018: DGPad Pro

Right after, an attempt, DGPad Pro, starts from scratch to give DGPad what it lacks: objects natively in space (each point has three coordinates, the view rotates around the coordinate system) and SVG drawing, where each object is a vector element, sharp at any zoom.

From October 2017 to April 2018, it gets points, lines, rays, segments, parallels, perpendiculars, midpoints and intersections. The project stops there: getting back a significant share of DGPad’s features required a disproportionate amount of work.

2021: a second attempt

A restart falls short: the SVG drawing of DGPad Pro then proves much slower than DGPad’s drawing on a canvas.

2026: DocGeo

On 13 September 2026, the code of DGPad Pro, unchanged since 2018, is taken up again with the Claude Code assistant and rewritten in TypeScript. SVG is now fast enough: browsers have improved, and the figure is only redrawn once per displayed frame, however many times the mouse moves.

The priority becomes faithfully reading existing figures, DGPad then GeoGebra, before construction.

What comes from DGPad Pro

  • Native 3D and rotation of the view, with its angle limits.
  • The drawing of each object in SVG.
  • Recomputing only the objects that depend on the one being moved.
